# Tutorial 7 — Cohort Selection

This tutorial derives **patient cohorts** from the feature table produced in Tutorial 6. Starting from a single patient-level feature dataset, you will create three targeted subsets using **Generalized Compute Code Objects** — each cohort is a registered dataset on the FCP, ready for downstream analytics or model training.

---

## What You Will Do

1. Define three Python Code Object scripts, each applying a different patient filter
2. Register and run all three Code Objects against the Patient Features dataset
3. Verify each cohort's size and composition with federated analytics

---

## What Is Cohort Selection?

A **cohort** is a well-defined subset of patients sharing one or more characteristics. Before running analytics or training a model, researchers typically restrict their population to a relevant subgroup — for example, patients within a specific age band, of a particular demographic, or meeting a clinical criterion.

In the Rhino FCP, cohort selection runs as a Code Object: the filtering logic executes locally on the client, and the output is a new registered dataset. This means:

- Raw patient records never leave the client network
- The filtered dataset is tracked in the FCP with its own UID and auto-inferred schema
- The same Code Object can be re-run at additional sites in a multi-site project

## The Three Cohorts

| Cohort | Filter | Output Dataset Name |
|---|---|---|
| **Males 30–40** | `age >= 30 AND age <= 40 AND is_male == 1` | `Cohort — Males 30–40` |
| **Females 30–40** | `age >= 30 AND age <= 40 AND is_female == 1` | `Cohort — Females 30–40` |
| **Race 8515** | `race_concept_id == 8515` | `Cohort — Race 8515` |

OMOP concept ID `8515` represents **Asian** in the OMOP vocabulary standard.

## How Cohort Code Objects Work

Each cohort is generated by running a **Generalized Compute Code Object** using the `generic-python-runner` container. The filtering script is passed at run time via `run_params["code"]` — not embedded in the Code Object definition. Inside the container, the script reads the Patient Features dataset from the mounted input path, applies a filter, and writes the result:

```python
import pandas as pd
import os

features_df = pd.read_csv("/input/dataset.csv")  # single input mounted here

cohort = features_df[some_filter].copy()

os.makedirs("/output", exist_ok=True)
cohort.to_csv("/output/dataset.csv", index=False)  # write for downstream mounting
outputs = [[cohort]]                               # register result with the container
```

The filter itself is plain pandas boolean indexing — no Rhino SDK inside the script.

## UI Alternative: Python Code Snippet

If you prefer not to use the notebook, you can create and run each cohort Code Object directly from the FCP Dashboard. Two approaches are supported:

**Option A — Generalized Compute (matches the notebook)**
1. Dashboard → Code → New Code Object → **Generalized Compute**
2. Select the `generic-python-runner` container image
3. Add 1 input (optionally set to the Patient Features schema), add 1 output (Auto-Generate Schema)
4. Run the Code Object and pass the cohort script as a run parameter (`run_params["code"]`)

**Option B — Python Code Snippet (UI paste-in)**
1. Dashboard → Code → New Code Object → **Python Code** → Code Snippet
2. Select **Python 3.9**, paste the relevant `code_snippets.py` script from `scripts` folder
3. Add 1 input (optionally set to the Patient Features schema), add 1 output (Auto-Generate Schema)
4. Click Run

The snippet versions use `[[features_df]] = inputs` and `outputs = [[cohort]]` — the platform injects the DataFrame directly rather than reading from file paths.

## Checking Your Work in the FCP Dashboard

### Reviewing the Code Objects

1. Navigate to **Projects → [Your Project] → Code**
2. Three new Code Objects appear:
   - `Cohort Selection — Males 30–40`
   - `Cohort Selection — Females 30–40`
   - `Cohort Selection — Race 8515`
3. Click the three-dot menu → **Show code object configuration** to inspect the filter logic

### Reviewing the Runs

1. Navigate to **Projects → [Your Project] → Code Runs**
2. Click any completed run:
   - Input: Patient Features dataset
   - Output: the corresponding cohort dataset
   - Logs: row counts before and after filtering

### Reviewing the Output Datasets

1. Navigate to **Projects → [Your Project] → Datasets**
2. Verify the three cohort datasets appear with non-zero row counts
3. Click any cohort → **Analytics** tab → confirm:
   - `age` range is 30–40 for the age-filtered cohorts
   - `is_male` = 1 for all rows in the Males cohort
   - `is_female` = 1 for all rows in the Females cohort
   - `race_concept_id` = 8515 for all rows in the Race 8515 cohort
